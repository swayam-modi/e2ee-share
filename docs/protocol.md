# Protocol Specification

This document specifies the wire format, signaling messages, cryptographic handshakes, and framing for `e2ee-share`.

## 1. URL Format

```text
https://<host>/r/<roomId>#<secret>
```

- `roomId`: 16 random bytes, base64url-encoded (22 characters). Generated by the signaling server.
- `secret`: 32 random bytes, base64url-encoded (43 characters). Generated locally by the sender's browser; never sent over HTTP or WebSocket to the server.
- The receiver reads `#<secret>` from `window.location.hash`, then wipes it from the address bar via `history.replaceState`.

## 2. Signaling REST API

| Method | Path         | Description                                                                           |
| ------ | ------------ | ------------------------------------------------------------------------------------- |
| `POST` | `/api/rooms` | Create a room. Returns `201 { roomId, senderToken, expiresAt }`. Rate-limited per IP. |
| `GET`  | `/api/ice`   | Returns `{ iceServers: [...] }` with ephemeral coturn REST credentials. Rate-limited. |
| `GET`  | `/healthz`   | Liveness check.                                                                       |
| `GET`  | `/ws`        | WebSocket upgrade for signaling.                                                      |

`senderToken` is a 32-byte cryptographically secure random token returned to the room creator to authenticate as the sender during WebSocket join. It is separate from the E2EE secret.

## 3. WebSocket Messages (Server Level)

Client → Server:

```json
{ "kind": "join", "roomId": "...", "role": "sender" | "receiver", "senderToken": "..." }
{ "kind": "signal", "envelope": { "seq": 0, "type": "...", "body": "...", "mac": "..." } }
{ "kind": "bye" }
```

Server → Client:

```json
{ "kind": "joined", "role": "sender" | "receiver", "peerPresent": true | false }
{ "kind": "peer-joined" }
{ "kind": "peer-left" }
{ "kind": "signal", "envelope": { "seq": 0, "type": "...", "body": "...", "mac": "..." } }
{ "kind": "error", "code": "...", "message": "..." }
```

## 4. End-to-End Authenticated Signaling Envelope

```typescript
type SignalType = 'pubkey' | 'wrapped-key' | 'key-ack' | 'sdp-offer' | 'sdp-answer' | 'ice';

interface Envelope {
  seq: number; // Monotonically increasing per sender, starts at 0
  type: SignalType;
  body: string; // Base64url payload or JSON string; never re-serialized
  mac: string; // Base64url HMAC-SHA-256
}
```

- `authKey`: Derived via HKDF-SHA-256:
  `HKDF-SHA-256(ikm = secret, salt = utf8(roomId), info = "e2ee-share v1 auth", length = 256 bits)`
- `mac`: `HMAC-SHA-256(authKey, utf8("${roomId}|${fromRole}|${seq}|${type}|${body}"))`

## 5. Binary Frame Format (DataChannel)

DataChannel configuration: `{ ordered: true }`, label `'transfer'`, `binaryType = 'arraybuffer'`.

```text
offset  size  field
0       1     version        = 0x01
1       1     type           = 0x01 CONTROL | 0x02 DATA
2       1     flags          bit0 = FINAL (last chunk of file)
3       4     fileIndex      u32 big-endian (0xFFFFFFFF for CONTROL)
7       4     seq            u32 big-endian (chunk index for DATA; msg counter for CONTROL)
11      n     ciphertext || 16-byte AES-GCM tag
```

- Header: 11 bytes.
- AAD: Header bytes `||` direction byte (`0x01` sender → receiver, `0x02` receiver → sender).
- Nonce (12 bytes): `[direction u8][0x00 0x00 0x00][fileIndex u32][seq u32]`
- Plaintext chunk size: 15,360 bytes (15 KiB). Max frame size: 15,387 bytes.
